# سلامت عملیات — نسخهٔ ۰٫۱۶

`operations-health` نمای آفلاین از اسناد دریافت موجود می‌سازد. این فرمان شبکه، registry یا کلید نمی‌خواهد؛ store موجود لازم است و غلط تایپی در مسیر، store تازه نمی‌سازد. خواندن اسناد زیر قفل مشترک انجام می‌شود؛ هنگام دریافت یا backup، فرمان با خطای روشن متوقف می‌شود.

```powershell
uv run gold --store local/market operations-health --output-dir local/operations-health/check-001
uv run gold --store local/market operations-health --refresh-manifest local/reports/refresh-v013/refresh-20261006T112826608764Z-53de8dd1c1a64a76b107d5aee3928066/refresh-run.json --allow-relocated-refresh --output-dir local/operations-health/check-002
```

خروجی باید پوشه‌ای جدید خارج از store باشد. JSON و متن فارسی کنار هم ذخیره می‌شوند؛ پوشهٔ موجود بازنویسی نمی‌شود. کد خروج صفر برای `clear`، سه برای `attention` یا `no_history` و دو برای خطای ورودی/خواندن است. در خطای نوشتن ممکن است پوشهٔ ناقص باقی بماند؛ موفقیت اعلام نمی‌شود.

## تفسیر وضعیت

- `no_history`: سند دریافت وجود ندارد؛ سلامت تأیید نشده است.
- `attention`: دریافت ناتمام، آخرین شکست یکی از جریان‌ها یا refresh غیرموفق نیاز به بررسی دارد.
- `clear`: در اسناد خوانده‌شده، آخرین دریافت هر جریان موفق بوده و دریافت ناتمام دیده نشده است. این وضعیت اعتبار داده، تازگی بازار یا آمادگی بک‌تست را تأیید نمی‌کند.

همهٔ اجراها حفظ می‌شوند؛ فقط آخرین اجرا بر اساس زمان شروع و سپس شناسه تعیین می‌شود. شناسهٔ جریان از عملیات، منبع/سری و مشخصات داده ساخته می‌شود؛ تغییر تاریخ پنجرهٔ هم‌پوشان جریان تازه نمی‌سازد. هش شناسه در JSON آمده است. شکست متوالی با موفقیت یا اجرای ناتمام قطع می‌شود. سند `running` حتی با وجود موفقیت جدیدتر همچنان آشکار می‌ماند؛ به‌طور خودکار شکست‌خورده یا زنده فرض نمی‌شود.

هش هر سند دریافت ثبت می‌شود. شمارش سند دریافت، وضعیت و شناسهٔ فایل کنترل می‌شوند؛ این فرمان audit کامل داده یا verify بستهٔ پژوهش نیست. کلید، پارامترهای ورودی، URL و متن استثنا در خروجی کپی نمی‌شوند. نام استثنای قدیمی فقط به دستهٔ محدود نگاشت می‌شود؛ `ValueError` به‌تنهایی علت دقیق خطا را ثابت نمی‌کند.

## پیوند refresh و انتقال دستگاه

بدون manifest صریح، علت HTTP دریافت‌های قدیمی قابل استنتاج نیست. با `--refresh-manifest`، کد امن خطا از قرارداد موجود refresh خوانده می‌شود و دریافت‌های ادعاشده باید با سند واقعی از نظر شناسه، وضعیت و شمارش تطبیق داشته باشند. این گزینه فقط یک گردش مشخص را پوشش می‌دهد؛ کد خطای بقیهٔ اجراها نامعلوم می‌ماند.

مسیر store باید یکسان باشد. `--allow-relocated-refresh` اجازه می‌دهد مسیر تاریخی دستگاه قبلی متفاوت باشد، با همان تطبیق اسناد؛ این استثنا به‌عنوان `relocated_explicitly` در خروجی ثبت می‌شود. خود manifest قدیمی تغییر نمی‌کند. این پیوند جای آزمون مستقل backup/restore را نمی‌گیرد.

## سهمیه و تلاش مجدد

سهمیهٔ باقیمانده یا تعداد درخواست‌های شبکه در اسناد قدیمی ثبت نشده؛ `quota_status=not_measured` است. تعداد دریافت‌ها معادل درخواست HTTP نیست: دریافت ممکن است صفحه‌بندی یا چند فایل سالانه داشته باشد. HTTP 429 نشانهٔ نیاز به بررسی سهمیه است، نه مقدار اندازه‌گیری‌شدهٔ سهمیه.

انتقال موجود برای هر درخواست حداکثر سه تلاش با timeout سی ثانیه و وقفه‌های یک و دو ثانیه دارد. فقط اتصال ناموفق و HTTP 429/500/502/503/504 دوباره تلاش می‌شوند. ورودی `attempts` اکنون فقط عدد صحیح یک تا سه می‌پذیرد؛ bool، صفر و بودجهٔ بالاتر پیش از شبکه رد می‌شوند. سقف مربوط به هر درخواست است، نه کل دریافت چندصفحه‌ای. کل گردش refresh خودکار دوباره اجرا نمی‌شود.

راهنمای گزارش پس از پایان این بودجه است: 429 بررسی سهمیه پیش از تلاش دستی؛ خطای موقت شبکه بررسی پیش از تلاش دستی؛ 403/مجوز/اعتبارسنجی/ذخیره‌سازی رفع علت پیش از تلاش؛ اجرای ناتمام بررسی شواهد پیش از اقدام. راهنما فرمان دریافت را اجرا نمی‌کند و برنامهٔ زمانی نمی‌سازد.

## runtime و شواهد واقعی

نسخه و پیاده‌سازی Python ساخت گزارش سلامت ثبت می‌شوند. محیط تاریخی دریافت‌های قبلی `not_recorded` است؛ نسخهٔ نرم‌افزار به‌تنهایی نسخهٔ Python را تعیین نمی‌کند. این ثبت مربوط به گزارش سلامت است و هنوز قرارداد runtime تاریخی بسته‌های پژوهش را توسعه نمی‌دهد.

روی store منتقل‌شده، ۶۵ سند شامل ۶۰ موفق و پنج ناموفق بررسی شدند. گزارش refresh قبلی `partial` است و خطای CFTC `HTTP_403`، اقدام رفع علت پیش از تلاش مجدد می‌گیرد. هیچ درخواست تازهٔ بازار یا تلاش مجدد شبکه در این تحویل اجرا نشده است. خروجی عملی در `local/operations-health/` محلی می‌ماند.

گام بعد: ثبت شواهد تعداد درخواست و پاسخ سهمیه برای دریافت‌های جدید، runtime همراه بستهٔ پژوهش و اجرای دریافت تازه پس از بررسی خطای CFTC؛ هیچ مقدار تاریخی ساخته نمی‌شود.
