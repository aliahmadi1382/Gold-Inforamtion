# Release validation

Release 0.3.0 is verified locally on Windows with Python 3.11 using the locked environment. The test suite contains 99 offline cases, including parameterized cases. CI repeats the suite on Windows and Linux with Python 3.11 and 3.12; the GitHub Actions result is the authority for remote status.

Verified behavior includes closed-bar validity, finite values, timezone awareness/DST, raw and normalized content hashes, atomic failed batches, exact-record idempotence, publication/retrieval cutoffs, future revision exclusion, delayed swing confirmation, mixed-stream rejection, price freshness, event-window arithmetic, restricted export, source-registry matching, FRED pagination/missing values/credential-safe errors, CFTC documented column mapping, generated-schema consistency and the repeatable synthetic demo. The source distribution and Python wheel build successfully.

Release 0.2 adds tests for acquisition success/failure, duplicate traces, safe manifest parameters, invalid stored kinds, registry drift, missing raw evidence, as-of coverage, ambiguous revisions, venue separation, null vs zero, reference-age/gap warnings, quality exit codes and scoped credential loading/restoration. The demo quality report passes at `2024-04-22T22:00:00Z` only with explicit synthetic allowance; its one stream has 80 unique observations. The same fixtures cannot certify readiness for real data.

The demo contains 80 fictional bars. Sample files can be regenerated with `uv run gold demo`; the store contains the raw bytes needed to resolve snapshot evidence IDs. Passing these tests verifies software mechanics, not market-data accuracy, statistical strategy performance or profitability.

Release 0.3 adds tests for the observed gold-history response schema, dates vs session instants, preserved weekends, absence of invented OHLC, future/duplicate date rejection, non-finite/invalid price rejection, safe service errors, missing keys, one-request acquisition, source rights, CLI failure manifests, quality capability separation and saved-byte reconciliation failures. Fixtures use invented prices in the provider's observed schema.

Live checks on 2026-10-05 acquired 5,415 gold-close rows and 719 DFII10 rows locally. All 6,134 records reconcile to their raw rows. The daily-close policy reports warnings for date-only prices, inferred gold units, weekend labels, missing FRED values and unknown historical release times. The separate OHLC policy correctly fails without bars. Detailed evidence remains in ignored `local/market/onboarding-report.json`; the [acquisition note](source-methodology/first-acquisition.fa.md) records coverage and limitations. These live observations do not establish independent gold-price accuracy or future service availability.

Other integration limits: the official CFTC ZIP returned HTTP 403 during initial implementation; its parser is tested with documented headers and synthetic counts. No vendor price history is bundled in the repository. News, calendar, WGC, LBMA and CME automatic connectors are not implemented. Their contracts, sources and remaining work are documented rather than represented as live features.
