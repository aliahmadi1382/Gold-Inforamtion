# تحویل ۰٫۱۴ — خلاصهٔ تغییرات و اولویت بررسی

تاریخ تحویل: ۸ اکتبر ۲۰۲۶. قابلیت جدید گزارش‌های بررسی‌شده را با comparator نسخهٔ ۲ خلاصه می‌کند؛ feed یا تحلیل LLM تازه ندارد.

## انتخاب مبنا

`refresh-report --baseline PATH` یک بستهٔ پژوهش مشخص را مبنا می‌گیرد. بدون این گزینه، فقط سندهای اجراهای قبلی `refresh-*` در همان `--output-dir` خوانده می‌شوند: اجرای پایان‌یافته با گزارش موفق، همان مسیر store و بزرگ‌ترین زمان برش انتخاب می‌شود. وضعیت کل `partial` مانع انتخاب گزارش سالم نیست. زمان فایل یا ترتیب نام پوشه معیار انتخاب نیست؛ دو مبنای هم‌زمان، سند ناخوانا یا بستهٔ خراب به شکست روشن منجر می‌شود و مبنای قدیمی‌تر جایگزین نمی‌شود.

انتخاب و گرفتن بایت‌های بررسی‌شده پیش از دریافت است. مبنای صریح مقدم است؛ پس از انتقال دستگاه، نخستین مبنا را صریح بدهید، چون `store_root` یا پوشهٔ قبلی متفاوت است. مبنا باید برشی حداکثر برابر شروع گردش جاری داشته باشد. مبنای آینده یا نامعتبر به `baseline_failed` یا `comparison_failed` می‌رسد؛ دریافت و گزارش جاری نتیجهٔ مستقل خود را حفظ می‌کنند.

یک سند ناخوانا در محدودهٔ جست‌وجوی خودکار نیز شکست انتخاب است؛ آن را بدون بررسی حذف نکنید. اجرای متوقف یا گزارش ناموفق مبنای خودکار نیست. مقایسهٔ بین storeها فقط با انتخاب صریح ممکن است؛ نتیجه همچنان به زمینهٔ گزارش وابسته است.

## تفکیک تغییر و اولویت

هر خلاصه در `reviews/review-.../` زیر پوشهٔ گردش، مستقل منتشر می‌شود. JSON شامل مقایسهٔ کامل، زمان برش‌ها، تعداد فیلدها، اولویت‌ها و JSON Pointer شاهد هر اولویت است. فارسی وضعیت بخش‌ها، زمینه و حداکثر ۱۵ نمونهٔ عدد/null را نمایش می‌دهد؛ جزئیات JSON حذف نمی‌شوند.

| گروه | تعریف |
| --- | --- |
| عدد | دو مقدار عددی حاضر؛ شامل مقدار اقتصادی، ضریب، تعداد یا پوشش؛ boolean عدد نیست |
| نتیجه یا وضعیت | تغییر سایر فیلدهای نتیجه |
| مقدار تهی | فیلد حاضر است اما یک طرف null دارد؛ صفر با null یکی نیست |
| حضور در نما | فیلد یا ردیف در یک طرف نیست؛ خروج از گزارش، حذف از پایگاه یا لغو رویداد نیست |
| شاهد | تغییر شناسه یا زمان شاهد طبق comparator؛ ممکن است عدد ثابت بماند |
| سن | تغییر سن شاهد/مشاهده، مستقل از دریافت تازه |

این تعدادها شمار **فیلد** هستند، نه رخداد اقتصادی مستقل. تغییر واحد/منبع/روش که هویت معنایی را عوض می‌کند، ورود و خروج جدا می‌ماند؛ تفاضل عدد میان تعریف‌های متفاوت ساخته نمی‌شود. تغییر تنظیمات، نسخه، رجیستری و cutoff در `context_changes` حفظ می‌شود. نبود COT در Schema قدیمی، `SCHEMA_INCOMPARABLE` است، نه موقعیت صفر یا دادهٔ مفقود.

| اولویت | قاعده |
| --- | --- |
| ۱ | گزارش ناموجود، دریافت ناموفق، تازگی/مقدار نامطلوب یا نامشخص، تقویم نامناسب، شکست مقایسه |
| ۲ | مبنای مفقود/خراب، بخش محدود/مفقود، تغییر زمینه/تعریف، Schema غیرقابل مقایسه، تغییر عدد/null/نما |
| ۳ | یادآوری شواهد BLS و vintageهای دقیقِ خارج از refresh خودکار |

اولویت، فوریت بررسی داده و عملیات است؛ جهت قیمت، ریسک معامله یا احتمال سود نیست. تغییر numeric نیز ممکن است تنها تغییر شمار نسخه‌های پایگاه باشد.

## قرارداد و بررسی

`RefreshReview` و `ReviewManifest` نسخهٔ ۱ دارند؛ قرارداد `RefreshRun` نسخهٔ ۱ و readerهای report/comparator قدیمی حفظ شده‌اند. خلاصه، قراردادی مستقل است و سند قدیمی refresh بازنویسی نمی‌شود.

| وضعیت | معنی |
| --- | --- |
| `compared` | مقایسه انجام شده؛ نتیجهٔ داخلی unchanged/context_only/changed است |
| `no_baseline` | مبنا نیست؛ تغییرات نامعلوم‌اند، نه صفر |
| `baseline_failed` | انتخاب یا بررسی مبنا شکست خورده |
| `comparison_failed` | مقایسه با مبنای منتخب ممکن نبوده |
| `report_failed` | گزارش جاری ساخته/بررسی نشده؛ اولویت عملیات ثبت می‌شود |

خطای نوشتن/بررسی خلاصه در CLI با `review_status: failed` و فقط نام نوع خطا ثبت می‌شود. متن استثنا، URL درخواست یا credential چاپ نمی‌شود. نتیجهٔ دریافت و گزارش مستقل باقی می‌ماند. کد خروج refresh برابر ۳ است اگر گردش partial/failed باشد یا خلاصه شکست بخورد؛ نبود مبنا به‌تنهایی خطا نیست. خطاهای عمومی ورودی/سیستم همچنان کد ۲ دارند.

بسته حاوی JSON، فارسی، کپی دقیق `refresh-run.json` و JSON گزارش قبل/بعد در صورت وجود است. Manifest مجموعهٔ فایل‌ها، هش و اندازه را ثبت می‌کند. نوشتن در `.incomplete-*`، بررسی و تغییر نام انجام می‌شود؛ خطای دیسک ممکن است پوشهٔ ناتمام بگذارد، اما خروجی قدیمی بازنویسی نمی‌شود.

`verify-review` با همین بسته وضعیت، comparator، تعدادها، اولویت‌ها، fingerprint و متن فارسی را دوباره می‌سازد. به SQLite، مسیر اولیه، رجیستری یا کلید نیاز ندارد. اصالت ناشر، وقوع شبکه، حقیقت اقتصادی یا ادعای نبود مبنا را مستقل تأیید نمی‌کند؛ انتخاب/شکست، فرادادهٔ عملیات است. بسته‌های اصلی با `load_verified_report` بررسی می‌شوند؛ کپی‌ها قرارداد و محاسبات را حفظ می‌کنند، نه تمام خام‌های بازار.

## اجرا و شواهد

```powershell
uv run gold --credentials-file local/credentials.env refresh-report --baseline PATH_TO_REPORT_BUNDLE
uv run gold review-refresh PATH_TO_REFRESH --baseline PATH_TO_REPORT_BUNDLE
uv run gold verify-review PATH_TO_REVIEW_BUNDLE
```

دو دستور آخر آفلاین‌اند. `review-refresh` بدون baseline صریح `no_baseline` می‌سازد و جست‌وجوی خودکار ندارد. اجرای مجدد پوشهٔ تازه ایجاد می‌کند.

در `C:\Projects\Gold` محیط قبلی در `local/environment-from-previous-device` حفظ و محیط Python 3.12.14 با lock بازسازی شد. هر ۴۴۹ آزمون پایه پاس شد. کنترل مستقل read-only پایگاه منتقل‌شده، هش ۸۸٬۷۰۷ نسخه، ۶۰ خام مستقیم و ۱۳ فایل آخرین گزارش را تأیید کرد.

خلاصهٔ واقعی از گردش ۶ اکتبر ۰٫۱۳ و مبنای ۰٫۱۲ ساخته شد: ۴۹ فیلد عددی، ۲ مقدار تهی، ۱ ورود/خروج، ۲۸۸ شاهد، ۹۸ سن و ۲۴ سایر نتایج تغییر دارند. CFTC HTTP 403 اولویت ۱ است؛ تغییر cutoff/نسخه جدا ثبت می‌شود. کنترل مستقل ۹۲۳ سمت فیلد و هر ۱۰ مسیر اولویت را با JSON ورودی تطبیق داد؛ ۱۴ بستهٔ پژوهش/مقایسهٔ قبلی همچنان معتبرند. هر ۴۸۶ آزمون، ۳۶ Schema، Ruff و ساخت بسته کنترل شدند. این کار **دریافت بازار نیست**؛ تازگی گزارش تاریخی به ۸ اکتبر تعمیم نمی‌یابد. نتیجه و رسیدها در `local/integration-v014/` می‌مانند و وارد Git نمی‌شوند.

گام بعد تثبیت عملیات و بازیابی است: backup سازگار و restore آزمایشی، سیاست سهمیه/خطا و هماهنگی writerها. دروازهٔ روش قیمت و زمان انتشار باز است. زمان‌بندی و اعلان اضافه نشده‌اند. [فصل پانزدهم](../education/15-refresh-review.fa.md) خواندن خلاصه را آموزش می‌دهد.
