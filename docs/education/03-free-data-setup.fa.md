# فصل ۳ — منابع رایگان و کلیدهای دسترسی

انتخاب تأییدشدهٔ شما: XAU/USD روزانه، گسترش به بازه‌های کوتاه‌تر در مراحل بعد، فقط منابع رایگان و عمومی، دریافت از API با کلیدهای شخصی Alpha Vantage و FRED. بررسی زیر در ۲۰۲۶-۱۰-۰۵ انجام شده است. رایگان بودن با حق انتشار فایل خام در GitHub یکسان نیست.

## نتیجهٔ بررسی اولیه

| منبع | کاربرد احتمالی | محدودیت فعلی |
| --- | --- | --- |
| [Alpha Vantage](https://www.alphavantage.co/documentation/) | تاریخچهٔ قیمت پایانی روزانهٔ طلا | اتصال با کلید شخصی آزموده شد؛ خروجی OHLC نیست؛ پوشش و هشدارها در گزارش محلی ثبت‌اند |
| [FRED](https://fred.stlouisfed.org/docs/api/api_key.html) | نرخ بهره، بازده واقعی و متغیرهای کلان | API به کلید شخصی نیاز دارد؛ اتصال در پروژه موجود است |
| [Dukascopy Historical Export](https://www.dukascopy.com/swiss/english/marketwatch/historical/) | فایل تاریخی در بازه‌های مختلف | مسیر دانلود انسانی قابل بررسی است؛ شرایط استفادهٔ سایت، خودکارسازی را محدود می‌کند و مسیر S3 مستند آن Requester Pays است |
| [Stooq](https://stooq.com/q/d/?s=xauusd) | نامزد بررسی قیمت XAU/USD | صفحه در این محیط بررسی مرورگر خواست و دریافت CSV موفق نشد؛ منبع عملیاتی اعلام نشده است |

طبق [راهنمای Alpha Vantage](https://www.alphavantage.co/support/)، پلن رایگان عمومی محدودیت درخواست روزانه دارد. پوشش مشاهده‌شدهٔ حساب در [گزارش نخستین دریافت](../source-methodology/first-acquisition.fa.md) ثبت شده است؛ این مشاهده تضمین پوشش درخواست‌های آینده نیست. [شرایط سرویس](https://www.alphavantage.co/terms_of_service/) نیز استفادهٔ فردی و غیرتجاری را از استفادهٔ تجاری جدا می‌کند. دادهٔ خام و نتایج وابسته به آن محلی می‌مانند.

## راه‌اندازی مسیر انتخاب‌شده: API رایگان

**API چیست؟** روشی است که برنامه از طریق آن داده را مستقیم از یک سرویس درخواست می‌کند. **API Key** رشته‌ای اختصاصی است که سرویس با آن درخواست‌های حساب شما و سهمیهٔ آن را تشخیص می‌دهد. مقدار نمونهٔ داخل مستندات، کلید شخصی شما نیست.

### دریافت کلید رایگان Alpha Vantage

1. [صفحهٔ رسمی دریافت کلید](https://www.alphavantage.co/support/#api-key) را باز کنید و بخش **Claim your Free API Key** را پیدا کنید.
2. در پرسش «Which of the following best describes you?» گزینه‌ای را انتخاب کنید که واقعاً وضعیت شما را توصیف می‌کند. در بخش Organization نام سازمان واقعی خود را وارد کنید؛ اگر مستقل هستید، می‌توانید ماهیت کار را با `Personal research` توضیح دهید. ایمیلی بنویسید که به آن دسترسی دارید.
3. بررسی انسانی یا مراحل تأیید فرم را، اگر نمایش داده شد، تکمیل کنید و درخواست کلید رایگان را ثبت کنید. ثبت‌نام و پذیرش شرایط حساب با خود شماست؛ خرید اشتراک جزو این مسیر نیست.
4. کلیدی را که سرویس پس از ثبت درخواست ارائه می‌کند در مقابل `ALPHAVANTAGE_API_KEY=` در فایل محلی قرار دهید.

در بررسی ۲۰۲۶-۱۰-۰۵، [صفحهٔ پشتیبانی رسمی](https://www.alphavantage.co/support/) سقف عمومی پلن رایگان را **۲۵ درخواست API در روز برای بیشتر مجموعه‌ها** اعلام می‌کند. دریافت کلید رایگان به معنی دسترسی به همهٔ محصولات پولی یا تضمین پوشش تاریخچهٔ طلا نیست؛ دسترسی مورد نیاز را با حساب خودتان بررسی خواهیم کرد.

### دریافت کلید رایگان FRED

1. [صفحهٔ حساب FRED](https://fredaccount.stlouisfed.org/login/secure/) را باز کنید. اگر حساب ندارید، گزینهٔ ثبت‌نام مانند **Register** یا **Create New Account** را انتخاب کنید. طبق [راهنمای رسمی](https://fredhelp.stlouisfed.org/fred/account/fred-account-features/register/)، ساخت حساب رایگان است.
2. فرم ثبت‌نام را با ایمیل در دسترس و رمز عبور تکمیل کنید؛ اگر تأیید ایمیل خواسته شد، آن را انجام دهید. سپس وارد حساب شوید.
3. [صفحهٔ درخواست یا مشاهدهٔ کلیدهای API](https://fredaccount.stlouisfed.org/apikeys) را باز کنید و درخواست کلید جدید را ثبت کنید. این بخش طبق [مستندات رسمی](https://fred.stlouisfed.org/docs/api/api_key.html) به ورود به حساب نیاز دارد.
4. اگر توضیح کاربرد برنامه خواسته شد، این متن با پروژهٔ فعلی سازگار است: `Personal research on gold prices and macroeconomic indicators using Python.` شرایط را بخوانید و در صورت پذیرش، درخواست را تکمیل کنید.
5. کلید اختصاصی ارائه‌شده را در مقابل `FRED_API_KEY=` در فایل محلی قرار دهید.

### ذخیرهٔ محلی و استفاده در پروژه

در این محیط، فایل `local/credentials.env` آماده شده است. آن را با ویرایشگر متن باز کنید و مقدار هر کلید را بعد از علامت `=` بنویسید. در نصب تازه، فایل `.env.example` را در آن مسیر کپی کنید؛ اگر فایل از قبل کلید دارد، روی آن کپی نکنید. قالب فایل:

```text
FRED_API_KEY=YOUR_FRED_KEY
ALPHAVANTAGE_API_KEY=YOUR_ALPHA_VANTAGE_KEY
```

کلید را در چت، README، اسکرین‌شات عمومی یا GitHub نگذارید. پوشهٔ `local/` از Git کنار گذاشته شده است. کلید خالی مجوز دسترسی ایجاد نمی‌کند. فایل نمونه عمداً کلید واقعی ندارد.

عبارت‌های `YOUR_FRED_KEY` و `YOUR_ALPHA_VANTAGE_KEY` را با کلید واقعی همان سرویس جایگزین کنید. نام فایل باید `credentials.env` بماند؛ آن را به `credentials.env.txt` تغییر ندهید.

بارگذاری این فایل صریح است. برای نمونه، دستور فعلی و پشتیبانی‌شدهٔ FRED:

```sh
uv run gold --credentials-file local/credentials.env fetch-fred DFII10 --start 2024-01-01 --end 2024-12-31
uv run gold --credentials-file local/credentials.env fetch-alpha-gold
uv run gold runs
```

برنامه کلیدها را در گزارش عملیات نمی‌نویسد. مقدارها فقط در محیط همان اجرای دستور بارگذاری می‌شوند. اتصال Alpha Vantage از نسخهٔ ۰٫۳ موجود است؛ هر اجرای آن یک درخواست می‌فرستد و قیمت پایانی را در قرارداد جداگانه ذخیره می‌کند. دادهٔ پایانی به کندل مصنوعی تبدیل نمی‌شود.

## مسیر جایگزین در صورت نیاز به OHLC

می‌توان فایل OHLC روزانه را به‌صورت انسانی از یک منبع مجاز دریافت و همراه نام ارائه‌دهنده، نوع قیمت، منطقهٔ زمانی، تاریخ دریافت و شرایط استفاده وارد کرد. تبدیل آن به CSV مشترک باید قابل پیگیری باشد. اگر فقط قیمت پایانی وجود داشته باشد، همان محدودیت فصل ۱ اعمال می‌شود.

در این محیط، کاربر آماده‌شدن کلیدها را اعلام کرده و هر دو اتصال آزموده شده‌اند. در نصب تازه، پس از واردکردن کلیدها فقط آماده‌شدن فایل را اعلام کنید، نه مقدار آن‌ها را. برای فهم نتیجهٔ دریافت، [فصل ۴](04-first-real-data.fa.md) را بخوانید.
